# Security Policy

## <svg width="18" height="18" viewBox="0 0 24 24" style="vertical-align:middle"><circle cx="12" cy="12" r="10" fill="#eab308"/><path d="M12 7v6" stroke="#fff" stroke-width="2" stroke-linecap="round"/><circle cx="12" cy="16.5" r="1.5" fill="#fff"/></svg> Reporting a Vulnerability

We take the security of this project seriously. If you discover a security vulnerability, please report it responsibly and follow the steps below:

- **Do not create a public GitHub issue.**
- **Privately disclose** the issue by emailing: [yuvarajuab@gmail.com](mailto:yuvarajuab@gmail.com)
- Please include as much of the following as possible:
  - A clear description of the vulnerability
  - Steps to reproduce the issue or proof of concept
  - The potential impact or risk
  - Relevant logs, screenshots, or supporting material

**Acknowledgment:**  
We aim to acknowledge all valid reports within 48 hours and will work to resolve confirmed issues as quickly as possible. We value and credit responsible disclosure.

## <svg width="18" height="18" viewBox="0 0 24 24" style="vertical-align:middle"><circle cx="12" cy="12" r="10" fill="#2563eb"/><path d="M12 8v4" stroke="#fff" stroke-width="2" stroke-linecap="round"/><circle cx="12" cy="16.5" r="1" fill="#fff"/></svg> Security Best Practices

To help maintain a secure environment, we recommend the following:

- Keep all dependencies and libraries up to date.
- Carefully review third-party packages before use.
- Never commit or share sensitive information such as credentials, API keys, or secrets.
- Follow secure coding and deployment practices.
- Regularly audit your environment for potential vulnerabilities.

## <svg width="18" height="18" viewBox="0 0 24 24" style="vertical-align:middle"><circle cx="12" cy="12" r="10" fill="#f87171"/><path d="M8 12h8M12 8v8" stroke="#fff" stroke-width="2" stroke-linecap="round"/></svg> Response Process

When a security vulnerability is reported, we will:

1. **Acknowledge** receipt of the report.
2. **Investigate and validate** the issue.
3. **Develop and test** a fix.
4. **Prepare and release** a patch or update.
5. **Publicly disclose** the issue and credit the reporter, unless anonymity is requested.

Thank you for helping keep our project and its users safe!
